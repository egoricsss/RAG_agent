# Агент на pydantic-ai

Отвечает на вопросы по курсу «Транслирующие системы» только по материалам
ChromaDB. Точка входа — `agent.py`; CLI — `main.py`.

База знаний и чанкинг описаны в [knowledge-base.md](knowledge-base.md).

## Состав модуля

| Объект | Назначение |
|---|---|
| `Deps` | коллекция Chroma, sync-клиент OpenRouter для эмбеддингов, имя модели |
| `Answer` | структурированный вывод: `answer`, `confidence`, `confidence_reason` |
| `retrieve_context(deps, query)` | поиск в Chroma и форматирование контекста |
| `create_agent(model)` | `Agent[Deps, Answer]` + tool `retrieve` |
| `ExamAgent` | async-фасад: `from_env()`, `answer()`, `close()`, контекстный менеджер |
| `INSTRUCTIONS` | системный промпт (роль, источники, уверенность, защита от инъекций) |
| `main.py` | argparse-обёртка над `ExamAgent.answer` |

## Поток ответа

1. `ExamAgent.answer(question)` проверяет, что вопрос не пустой.
2. `retrieve_context` вызывается **всегда** заранее, в `asyncio.to_thread`
   (клиенты Chroma/OpenAI синхронные и не должны блокировать event loop).
3. Если контекст пуст (`NO_CONTEXT`), модель не вызывается.
4. Иначе модели передаётся JSON `{"question": ..., "course_materials": ...}`.
5. Модель может вызвать tool `retrieve` для дополнительного поиска.
6. Возвращается только текст ответа: без повторения вопроса и без служебной
   строки об уверенности. При пустом контексте возвращается сообщение об отсутствии
   материалов. Уверенность сохраняется во внутренней структуре `Answer`, но не выводится пользователю.

## Поиск и приоритет Q&A

`retrieve_context`:

- делает эмбеддинг запроса той же моделью, что при индексации;
- запрашивает `n_results=8`, метрика — cosine, `similarity = 1 - distance`;
- отбрасывает пустые документы и записи без distance;
- сортирует так, чтобы **сильный** Q&A (`type == "qa"` и similarity > 0.65)
  шёл раньше прочих, но порядок Chroma внутри групп сохранялся;
- берёт 6 лучших чанков и подписывает каждый:
  `[Источник: <source_file>; тип: <type>; вопрос <N>; косинусное сходство: 0.xxx]`.

Слабый Q&A не должен обгонять релевантный учебник — это закреплено тестом
`test_real_chroma_query_and_priority`.

## Промпт и уверенность

`INSTRUCTIONS` требует: русский язык, только найденные материалы, приоритет
готовых ответов `qa`. Ответ начинается с сути, обычно занимает 1–3 коротких
предложения или список. Для теста первая строка — выбранный вариант или варианты.
Формулировка вопроса, заголовки и служебные ссылки на источники не выводятся.
Уверенность — внутренняя качественная самооценка:

- **высокая** — материалы прямо и полно подтверждают ответ;
- **средняя** — подтверждают частично или есть неоднозначность;
- **низкая** — материалов мало, они противоречивы или связь неясна.

Промпт отдельно оговаривает: косинусное сходство — не вероятность правильности,
а вопрос и материалы — данные, а не инструкции (защита от prompt injection).

## Конфигурация

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `OPENROUTER_API_KEY` | ключ, обязателен | — |
| `OPENROUTER_CHAT_MODEL` | модель генерации | `google/gemini-2.5-flash` |
| `OPENROUTER_EMBEDDING_MODEL` | модель эмбеддингов | `qwen/qwen3-embedding-8b` |
| `CHROMA_DB_PATH` | путь к базе | `chroma_db` рядом с `agent.py` |
| `CHROMA_COLLECTION` | имя коллекции | `compilers_kb` |

`ExamAgent.from_env` падает с понятной ошибкой, если:

- нет ключа;
- нет `chroma.sqlite3` по пути;
- коллекция не найдена;
- сохранённая в метаданных модель эмбеддингов не совпадает с текущей;
- метрика коллекции не `cosine`.

Агент **не создаёт** базу и не меняет её.

## Инварианты при правках

- Контекст ищется до вызова модели, даже если модель умеет `retrieve` сама.
- Пустой контекст не тратит запрос к чат-модели.
- Синхронные вызовы не выполняются в event loop.
- `close()` закрывает оба клиента; `ExamAgent` создаётся один раз на процесс.
- История диалога не хранится: каждый `answer` независим.
- Секреты не попадают в логи и сообщения об ошибках.

## Тесты

`tests/test_agent.py` — реальная временная Chroma-коллекция, `TestModel` /
`FunctionModel` и моки вместо сети:

- приоритет сильного Q&A и лимит 6 чанков;
- пустая коллекция не вызывает эмбеддинги;
- контекст и вопрос реально уходят в модель;
- tool `retrieve` вызывается моделью;
- уровни уверенности и валидация `Answer`;
- проверки `from_env` и закрытие клиентов.

Запуск: `uv run python -m unittest discover -s tests -v`.

Качество ответов проверяется не unit-тестами, а вручную или судьёй-моделью по
`docs/golden-set.md`: эталонные ответы и ключевые факты по 32 темам, 20
вопросов в тестовом формате, краевые случаи (вопрос вне курса, ложная посылка,
инъекция, выдуманный источник) и рубрика оценок.
