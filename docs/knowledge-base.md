# База знаний и индексация

Векторная база ChromaDB — единственный источник фактов для агента. Наполняется
скриптом `../utils/pdf_embeding_converter.py`, читается через `agent.py`.

Как агент использует поиск, описано в [agent.md](agent.md).

## Параметры коллекции

| Параметр | Значение |
|---|---|
| Путь | `./chroma_db` (локально, в git не попадает) |
| Коллекция | `compilers_kb` |
| Метрика | cosine (`hnsw:space`) |
| Модель эмбеддингов | `qwen/qwen3-embedding-8b` |
| Размерность | 4096 |

Модель и метрика записываются в метаданные коллекции. При несовпадении модели
и скрипт, и агент останавливаются с ошибкой — переиндексация только через
`--reset`.

## Что лежит в базе

1. **Q&A** (`type: "qa"`) — вопросы к зачёту с развёрнутыми ответами из
   `Ответы_Транслирующие_системы.md`, ~98 чанков.
2. **Пособия и лекции** (`type: "textbook"`) — PDF из `pdfs/`, ~330+ чанков.

Пустые сканы без текстового слоя пропускаются с сообщением `[!] Пустой PDF`.
Основные сведения по этим темам обычно уже есть в Q&A и текстовых PDF.

## Метаданные чанков

```python
# type == "qa"
{
    "type": "qa",
    "question_number": 29,          # int
    "question": "Транслирующие грамматики. ...",
    "chunk_index": 0,
    "chunks_total": 3,
    "source_note": "Пояснение из исходного файла (до 500 символов)",
    "source_file": "Ответы_Транслирующие_системы.md",
    "embedding_model": "qwen/qwen3-embedding-8b",
}

# type == "textbook"
{
    "type": "textbook",
    "source_file": "1_Транслирующие_грамматики_плюс_АТГ.pdf",
    "chunk_index": 0,
    "chunks_total": 13,
    "embedding_model": "qwen/qwen3-embedding-8b",
}
```

В каждый Q&A-чанк добавляется заголовок
`Вопрос <N>. <текст вопроса>`, чтобы фрагмент был понятен без соседей.

## Чанкинг

| Тип | chunk_size | overlap | ID |
|---|---|---|---|
| Q&A | 1100 | 180 | `qa_q29_c00` |
| Textbook | 850 | 150 | `pdf_<stem>_c0000` |

Текст режется по абзацам/строкам, длинные блоки — принудительно; overlap
переносит хвост предыдущего чанка. Из PDF сохраняются маркеры `[Страница N]`.

## Команды

```bash
# Полная переиндексация (удаляет коллекцию)
uv run utils/pdf_embeding_converter.py --reset

# Только Q&A или только PDF
uv run utils/pdf_embeding_converter.py --only-qa --reset
uv run utils/pdf_embeding_converter.py --only-pdf --reset

# Проверить чанки без обращений к API
uv run utils/pdf_embeding_converter.py --dry-run

# Поиск по готовой базе
uv run utils/pdf_embeding_converter.py --query "Что такое транслирующая грамматика?"
uv run utils/pdf_embeding_converter.py --query "..." --top-k 8
```

Полезные флаги: `--qa`, `--pdf-dir`, `--db`, `--collection`, `--model`.
Нужен `OPENROUTER_API_KEY` (кроме `--dry-run`).

## Поведение записи

- Эмбеддинги считаются батчами по 24, с повторами и backoff при ошибках.
- Запись — `upsert` батчами по 80.
- Перед загрузкой удаляются все чанки тех `source_file`, которые есть в текущем
  прогоне; остальные источники не трогаются.
- `--reset` удаляет коллекцию целиком.

## Правила

- Не меняй модель эмбеддингов без полной переиндексации: старые и новые
  векторы несовместимы.
- Не пересоздавай `chroma_db/` без явной просьбы: это долгая платная операция.
- Индексирование и агент должны использовать одну модель (`OPENROUTER_EMBEDDING_MODEL`).
- После изменения чанкинга или метаданных обнови `agent.md` и тесты поиска.
