# Telegram-бот

Закрытый бот для личной переписки: принимает вопросы текстом или фото теста,
отвечает через `ExamAgent`. Точка входа — `telegram_bot.py`, доступ хранится в
`access_store.py`.

Устройство агента описано в [agent.md](agent.md). Пользовательская инструкция —
в [README.md](../README.md#закрытый-telegram-бот).

## Состав модуля

| Объект | Назначение |
|---|---|
| `BotConfig` | конфигурация из env, валидация при старте |
| `AccessStore` | SQLite: пользователи, приглашения, флаг инициализации |
| `PrivateBot` | авторизация, хендлеры, альбомы, ответы |
| `extract_questions` | vision-модель переписывает задания с фото в JSON |
| `split_message` | разбиение на части ≤ 4096 «телеграм-единиц» |
| `main` | сборка `Application`, регистрация хендлеров, polling |

## Конфигурация

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | токен BotFather, обязателен | — |
| `TELEGRAM_SUPER_ADMIN_ID` | числовой ID админа, обязателен | — |
| `TELEGRAM_ALLOWED_USER_IDS` | стартовый список ID через запятую | пусто |
| `TELEGRAM_ACCESS_DB_PATH` | файл базы доступа | `telegram_access.sqlite3` |
| `OPENROUTER_VISION_MODEL` | распознавание фото | `google/gemini-2.5-flash` |

Некорректный ID или отсутствие админа останавливают запуск (fail closed).
`TELEGRAM_ALLOWED_USER_IDS` читается **только при создании** базы: при уже
инициализированной базе переменная игнорируется.

## Авторизация

- Работают только личные чаты (`effective_chat.type == "private"`); группы и
  каналы игнорируются.
- Разрешён супер-админ по ID или пользователь, записанный в `AccessStore`.
- Приглашение (`/add_user @username`) одноразовое: при первом обращении
  username привязывается к числовому ID и удаляется из приглашений. Смена
  username не переносит доступ.
- `authorize()` обновляет username и снимает прежнюю привязку, если username
  теперь принадлежит другому ID.

## Схема SQLite

```sql
settings(key TEXT PRIMARY KEY)                 -- маркер 'initialized'
users(id INTEGER PRIMARY KEY, username TEXT)
invitations(username TEXT PRIMARY KEY)
```

Стартовые ID вставляются один раз, при создании таблиц.

## Хендлеры

| Команда | Кто | Действие |
|---|---|---|
| `/start`, `/help` | участник | подсказка; админу — список команд |
| `/add_user @username` | админ | создать приглашение |
| `/remove_user @username\|ID` | админ | отозвать доступ или приглашение |
| `/remove_all` | админ | очистить всех и все приглашения |
| `/users` | админ | список ID, username и приглашений |

Текст и фото от неавторизованных молча игнорируются.

## Обработка вопроса

**Текст:** `send_answer` → `ExamAgent.answer` → ответ режется на части по 4096.

**Фото:**

1. Одиночное фото обрабатывается сразу; альбом копится `ALBUM_DELAY = 2.0` с
   после последнего фото.
2. Фото сортируются по `message_id`, скачиваются все, лимит — `MAX_PHOTOS = 10`
   и `MAX_PHOTO_BYTES = 10 МиБ` на файл.
3. `extract_questions` просит vision-модель вернуть JSON
   `{"questions": [...]}` по strict JSON Schema; модель **не решает** задания,
   неразборчивое помечает `[неразборчиво]`.
4. Распознанные задания показываются пользователю (чтобы заметить ошибку OCR).
5. На каждое задание отдельно вызывается `send_answer`; подпись к фото
   добавляется как комментарий пользователя.
6. Ошибка одного задания не прерывает остальные.

`split_message` считает символы вне BMP за две единицы и режет по переводу
строки, если он есть поблизости.

## Инварианты при правках

- Любая точка перед отправкой сообщения проверяет `still_authorized`: доступ
  могли отозвать во время OCR или ответа.
- `cancel_albums` вызывается при `/remove_user` и `/remove_all`; фоновые задачи
  отменяются, `shutdown` их дожидается и закрывает `AccessStore` и `ExamAgent`.
- Ответы и тексты ошибок не раскрывают внутренние детали и секреты.
- Ключи и база доступа не коммитятся; файл БД ограничивается по доступу.
- Лимиты Telegram (10 фото в альбоме, 4096 символов, 10 МиБ) не повышать —
  это ограничения платформы.

## Тесты

`tests/test_telegram_bot.py` — моки Telegram, vision-модели и `ExamAgent`:

- конфиг валидируется и падает fail closed;
- группы и чужие пользователи не доходят до хендлеров;
- текст, одиночное фото, альбом (сортировка и изоляция по пользователю);
- пустые и слишком большие фото, пустой OCR, частичная ошибка ответа;
- приглашения, привязка username к ID, отзыв доступа во время OCR/ответа;
- персистентность базы и игнорирование env после инициализации;
- `shutdown` отменяет альбомы и закрывает клиентов.

Запуск: `uv run python -m unittest discover -s tests -v`.
