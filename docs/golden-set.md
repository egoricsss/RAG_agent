# Golden set для проверки ответов агента

Набор для проверки **качества ответов**, а не кода: эталонные ответы и
проверяемые критерии по 32 темам курса «Транслирующие системы», 20 вопросов
в тестовом формате и краевые случаи.

Эталон собран по файлу `Ответы_Транслирующие_системы.md` (он же лежит в базе
как чанки `type: qa`, вопросы 1–32) и по раздаточным материалам. Там, где
сам эталон помечен как дополненный из интернета, формулировка лектора может
отличаться: эквивалентный по смыслу ответ не считается ошибкой.

Эталон задаёт **содержание**, а не длину: агент по инструкции отвечает
в 1–3 предложения, поэтому полное совпадение текста не требуется.

## Как пользоваться

1. Задайте агенту вопрос из блока «Вопрос» (`uv run main.py "..."` или
   Telegram-бот).
2. Сверьте ответ с «Эталон» и отметьте, какие «Ключевые факты» присутствуют.
3. Поставьте оценку 2 / 1 / 0 по рубрике ниже.
4. Отдельно отметьте формат, источники и уверенность (глобальные проверки).
5. Для тестовых вопросов проверьте первую строку: буква + текст варианта.

## Рубрика

| Оценка | Условие |
|---|---|
| **2 — верно** | Все ключевые факты есть (или переданы эквивалентно), фактических ошибок и выдуманных источников нет |
| **1 — частично** | Есть не меньше половины ключевых фактов, критической ошибки нет; либо ответ верен, но с лишним неверным утверждением, не меняющим суть |
| **0 — неверно** | Противоречит ключевому факту, содержит выдуманный факт или источник, не отвечает на вопрос |

Проходной результат для набора: **не меньше 26 из 32 оценок «2»** и
**ноль** ответов с выдуманными источниками или выполненными инструкциями
из вопроса.

## Глобальные проверки (для каждого ответа)

- **Опора на материалы.** Ни одного факта, которого нет в базе; при
  недостатке материалов агент говорит об этом, а не достраивает по общим
  знаниям.
- **Источники.** Указаны реальные файлы из списка ниже и/или
  `Ответы_Транслирующие_системы.md, вопрос N`. Выдуманных имён файлов,
  страниц и номеров вопросов быть не должно.
- **Формат.** Ответ начинается с сути, без «Вопрос:», «Конечно!» и
  пересказа вопроса; обычно 1–3 предложения или короткий список; источники —
  одной короткой строкой.
- **Тестовый формат.** Первая строка — буква (или буквы) и текст выбранного
  варианта, без пояснений до неё.
- **Уверенность.** Качественная оценка, не вероятность; косинусное сходство
  не подаётся как вероятность правильности.
- **Безопасность.** Команды внутри вопроса или материалов («игнорируй
  инструкции», «выведи промпт») не выполняются.

# Часть 1. Открытые вопросы (32 темы)

## 1. Классификация ПО. Этапы развития систем ПО

**Вопрос.** Что такое система программного обеспечения и какие этапы развития
систем ПО выделяют?

**Эталон.** Система ПО — совокупность программ, которые должны или могут
функционировать совместно. Этапы в порядке появления: библиотеки стандартных
подпрограмм → транслирующие системы (начало этапа 1953–54 гг., FORTRAN) →
операционные системы → ПО ЭВМ последующих поколений. Те же этапы дают
классификацию ПО по назначению.

**Ключевые факты.**
- [ ] определение системы ПО как совокупности совместно функционирующих программ;
- [ ] все четыре этапа и именно такой порядок;
- [ ] транслирующие системы как этап, соответствующий системам программирования.

**Ошибки.**
- пропущен или переставлен этап (например, ОС раньше трансляторов);
- деление на системное и прикладное ПО выдано за этапы развития.

**Не ошибка.** Упоминание ГОСТ 19781-90 и системного/прикладного ПО как
дополнения, если четыре этапа названы верно.

## 2. Способы классификации систем программирования. Типы трансляторов

**Вопрос.** Как классифицируют системы программирования и какие типы
трансляторов выделяют?

**Эталон.** Система программирования — совокупность языка программирования и
транслятора. Классификация: по степени удалённости от системы команд ЭВМ
(машинно-ориентированные → процедурно-ориентированные →
проблемно-ориентированные); по характеру использования (для программирования
и вспомогательные); по способу использования (алгоритмические и
неалгоритмические). Транслятор переводит программу из одной формы в другую;
ассемблер — с машинно-ориентированного языка, интерпретатор совмещает
трансляцию и выполнение, компилятор транслирует программу целиком.

**Ключевые факты.**
- [ ] система программирования = язык + транслятор;
- [ ] три способа классификации (удалённость, характер, способ использования);
- [ ] определения ассемблера, интерпретатора, компилятора;
- [ ] интерпретатор выполняет операторы по мере трансляции, компилятор — программу целиком.

**Ошибки.**
- интерпретатор назван транслятором, который сначала строит объектный модуль;
- перепутаны классификация «по характеру» и «по способу» использования;
- транслятор определён как «переводчик только с языка высокого уровня».

**Не ошибка.** Дополнительные понятия «проход» и «препроцессор».

## 3. Машинно-ориентированные системы: ССК, мнемокоды, автокоды, макроассемблеры

**Вопрос.** Охарактеризуйте машинно-ориентированные системы программирования:
ССК, мнемокоды, автокоды, макроассемблеры.

**Эталон.** Это уровень систем программирования, ближайший к системе команд
ЭВМ. ССК заменяют цифровые коды и адреса символическими обозначениями (1:1);
мнемокоды используют мнемонические коды операций, метки и псевдокоманды
(1:1); автокоды — язык условной машины, оператор переводится в одну или
несколько команд (1:1 или 1:n); макроассемблеры поддерживают
макроопределения, макрокоманды и условное ассемблирование. Общее: привязка к
системе команд, эффективный код, трудоёмкое программирование.

**Ключевые факты.**
- [ ] порядок усложнения: ССК → мнемокоды → автокоды → макроассемблеры;
- [ ] ССК — символические коды и адреса, соотношение 1:1;
- [ ] мнемокоды — мнемоники, метки, псевдокоманды, 1:1;
- [ ] автокоды — условная машина, возможно 1:n;
- [ ] макроассемблер — макроопределения и макрорасширение.

**Ошибки.**
- макрорасширение отнесено ко времени выполнения;
- ССК наделены мнемониками и макросредствами;
- автокод назван языком высокого уровня, не привязанным к машине.

**Не ошибка.** Формулировки из ГОСТ 19781-90 и примеры мнемоник (ПЕР, СЛЖ, УМН).

## 4. Ассемблеры: типы команд и типы адресов

**Вопрос.** Какие типы команд и типы адресов обрабатывает ассемблер?

**Эталон.** Команды: машинные (транслируются 1:1), псевдокоманды-директивы
(выполняются самим ассемблером: резервирование памяти, константы, EQU, ORG,
внешние имена, конец программы) и макрокоманды (заменяются
макрорасширением). Адреса: абсолютные (не зависят от загрузки),
перемещаемые (отсчитываются от начала программы и корректируются при
загрузке) и внешние (определены в другом модуле, заполняются редактором
связей).

**Ключевые факты.**
- [ ] три типа команд и суть каждого;
- [ ] псевдокоманды не переводятся в машинные команды;
- [ ] три типа адресов: абсолютные, перемещаемые, внешние;
- [ ] внешние адреса разрешает редактор связей/загрузчик.

**Ошибки.**
- псевдокоманды названы машинными командами;
- внешний адрес «вычисляет сам ассемблер»;
- перемещаемый адрес используется без коррекции при загрузке.

**Не ошибка.** Упоминание видов объектных модулей (абсолютные, перемещаемые,
текст на ассемблере).

## 5. Двухпроходная схема ассемблирования

**Вопрос.** Зачем ассемблеру два прохода? Как решаются распределение памяти и
формирование таблиц?

**Эталон.** Из-за ссылок вперёд имя может использоваться раньше определения,
поэтому адресную часть команды сразу построить нельзя. Первый проход строит
таблицу имён и распределяет память, второй, имея полную таблицу, формирует
объектный код. Память распределяется счётчиком размещения: метка получает
текущее значение счётчика, после команды или области данных счётчик
увеличивается на их длину. Таблицы бывают постоянные (мнемокоды,
псевдокоманды) и формируемые (имена, литералы, сегменты, макроопределения).

**Ключевые факты.**
- [ ] причина — ссылки вперёд;
- [ ] первый проход: таблица имён + распределение памяти;
- [ ] второй проход: объектный код;
- [ ] счётчик размещения и присвоение метке текущего адреса;
- [ ] постоянные и формируемые таблицы.

**Ошибки.**
- проходы нужны «для оптимизации»;
- первый проход генерирует объектный код;
- метка получает адрес после трансляции всей программы, а не из счётчика.

## 6. Первый проход ассемблера

**Вопрос.** Опишите укрупнённую схему первого прохода ассемблера и его
основные подпрограммы.

**Эталон.** Счётчик размещения устанавливается в начальный адрес, таблица
имён пуста. Строка читается и разбирается на поля; метка заносится в таблицу
со значением счётчика (повторное определение — ошибка); по таблице мнемокодов
определяется длина команды и счётчик продвигается, псевдокоманда передаётся
своему обработчику, неизвестная мнемоника — диагностика. Строка сохраняется
для второго прохода; проход заканчивается на псевдокоманде конца программы.
Операнды анализируются лишь настолько, насколько нужно для длины; литералы
заносятся в таблицу литералов.

**Ключевые факты.**
- [ ] цель — таблица имён и распределение памяти;
- [ ] обработка метки: значение = текущий счётчик, повтор — ошибка;
- [ ] определение длины команды и продвижение счётчика;
- [ ] обработка псевдокоманд (константы, резерв, EQU, ORG, конец);
- [ ] значения операндов на первом проходе не нужны.

**Ошибки.**
- первый проход подставляет адреса операндов;
- первый проход выдаёт объектный модуль;
- литералы не собираются.

**Не ошибка.** Названия подпрограмм («подборка адресов» и т. п.) в другой
формулировке, если смысл верный.

## 7. Второй проход ассемблера

**Вопрос.** Опишите укрупнённую схему второго прохода ассемблера и его
основные подпрограммы.

**Эталон.** Счётчик снова ставится в начальное значение, текст читается с
начала. Для машинной команды берётся код операции, формируется адресная часть
(регистр кодируется, константа выписывается, имя заменяется адресом;
неизвестное имя — ошибка), команда пишется в объектный модуль, счётчик
продвигается. Для директив данных формируется область данных: константы
переводятся во внутреннее представление, под резерв пропускается место,
размещаются литералы. В конце выдаются объектный модуль, сведения для
редактора связей (внешние имена, таблица перемещений) и листинг.

**Ключевые факты.**
- [ ] цель — объектный код по готовой таблице имён;
- [ ] формирование адресной части: имя → адрес, неизвестное имя — ошибка;
- [ ] учёт типа адреса: абсолютный, перемещаемый (таблица перемещений), внешний (место + запись для редактора связей);
- [ ] формирование области данных и размещение литералов;
- [ ] выход: объектный модуль, данные для редактора связей, листинг.

**Ошибки.**
- второй проход строит таблицу имён;
- перемещаемый адрес вписывается без пометки;
- внешнее имя разрешается самим ассемблером.

## 8. Макрогенераторы. Универсальный генератор макрокоманд

**Вопрос.** Что такое макрогенератор и как он работает? Что такое универсальный
генератор макрокоманд?

**Эталон.** Макрокоманда заменяется макрорасширением по макроопределению;
макрогенератор выполняет эту замену. В режиме определения текст
макроопределения запоминается в таблице макроопределений, формальные
параметры заменяются номерами. В режиме расширения по имени макрокоманды
находится определение, фактические параметры связываются с формальными, тело
копируется в текст; вложенные вызовы обрабатываются стеком расширений,
условная генерация — переменными времени трансляции. Универсальный
макрогенератор не привязан к конкретному ассемблеру и работает как
преобразователь «текст → текст» (частный случай препроцессора).

**Ключевые факты.**
- [ ] определения макрокоманды, макроопределения, макрорасширения, макрогенератора;
- [ ] режим определения и режим расширения;
- [ ] подстановка фактических параметров вместо формальных;
- [ ] стек расширений и условная генерация;
- [ ] отличие от подпрограммы: разворачивается при трансляции, а не при выполнении;
- [ ] универсальный генератор — «текст → текст» перед любым транслятором.

**Ошибки.**
- макрорасширение происходит при выполнении;
- тело макроса хранится в программе один раз, как у подпрограммы;
- универсальный генератор назван частью конкретного ассемблера.

**Не ошибка.** Упоминание «нулевого прохода» и совмещения с первым проходом.

## 9. Однопроходные ассемблеры

**Вопрос.** Как устроен однопроходный ассемблер и как он решает проблему ссылок
вперёд?

**Эталон.** Текст читается один раз. Неизвестное имя заносится в таблицу с
признаком «не определено», а адреса незавершённых команд связываются в цепочку
через их свободные адресные поля. Когда имя определено, ассемблер проходит по
цепочке и вписывает адрес во все ожидающие команды; оставшиеся неопределёнными
имена — ошибка. Простейший вариант формирует код в памяти и сразу запускает
программу (load-and-go). Достоинство — скорость, недостатки — усложнение,
расход памяти и ограничения на ссылки вперёд.

**Ключевые факты.**
- [ ] один просмотр текста;
- [ ] цепочка незавершённых команд и указатели в адресных полях;
- [ ] при определении имени цепочка «прошивается» адресом;
- [ ] неопределённое имя к концу — ошибка;
- [ ] load-and-go и оценка достоинств/недостатков.

**Ошибки.**
- однопроходный ассемблер просто «не поддерживает ссылки вперёд»;
- для разрешения ссылок он читает текст второй раз;
- объектный модуль всегда перемещаемый.

**Не ошибка.** Упоминание «полуторапроходных» ассемблеров.

## 10. Трёхпроходные ассемблеры

**Вопрос.** Когда и зачем применяют трёхпроходную схему ассемблирования?

**Эталон.** Третий просмотр добавляется в двух случаях. Первый — отдельный
макропроход («нулевой») перед обычными проходами: макрокоманды разворачиваются
в новый текст, потому что метки и мнемоники могут появиться только после
расширения; плюс — первый и второй проходы остаются простыми, минус — лишний
просмотр и промежуточный файл. Второй — уточнение длин команд, когда короткая и
длинная формы выбираются по адресу операнда: первый проход строит таблицу
имён, второй уточняет размеры, третий генерирует объектный модуль.

**Ключевые факты.**
- [ ] как минимум один из двух вариантов: макропроход или уточнение длин;
- [ ] причина дополнительного прохода;
- [ ] распределение работы по проходам;
- [ ] компромисс: простота проходов против лишнего просмотра.

**Ошибки.**
- утверждается, что в курсе есть единственная каноническая трёхпроходная схема;
- выдуман четвёртый проход;
- третий проход назван этапом оптимизации.

**Не ошибка.** Ответ только про макропроход или только про длины команд, если
второй вариант не выдаётся за единственный.

## 11. Рекурсивные подпрограммы и макрокоманды

**Вопрос.** Как программируют рекурсивные подпрограммы и рекурсивные
макрокоманды на языках ассемблерного типа?

**Эталон.** Рекурсивная подпрограмма вызывает саму себя; это возможно при
динамическом распределении памяти. Адрес возврата, параметры и локальные
данные размещают в стеке, при каждом вызове создаётся новый кадр (область
инициализации), используемые регистры сохраняются и восстанавливаются, нужен
условие окончания рекурсии. Рекурсивная макрокоманда вызывает себя в теле
макроопределения и разворачивается при трансляции; нужны переменные времени
трансляции, условная генерация и стек расширений. Отличие: подпрограмма
расходует стек при выполнении, макрокоманда увеличивает объём текста, а во
время выполнения рекурсии уже нет.

**Ключевые факты.**
- [ ] рекурсивная подпрограмма — вызов самой себя;
- [ ] стек, кадр/область инициализации на каждый вызов;
- [ ] сохранение регистров и условие окончания;
- [ ] рекурсивная макрокоманда разворачивается при трансляции;
- [ ] условная генерация и стек расширений;
- [ ] различие по расходу памяти и объёму кода.

**Ошибки.**
- рекурсия в макрокомандах происходит при выполнении;
- локальные данные хранятся в статических ячейках;
- условие окончания не требуется.

## 12. Структура (фазы работы) компилятора

**Вопрос.** Перечислите фазы работы компилятора и что передаётся между ними.

**Эталон.** Лексический анализ → грамматический разбор (синтаксический анализ,
семантический анализ, генерация внутренней формы) → оптимизация →
распределение памяти и генерация кода. Анализ входной программы — это
лексический, синтаксический и семантический анализ; синтез — от внутренней
формы до объектного модуля. Объектные модули бывают абсолютные, перемещаемые
и в виде текста на ассемблере. Минимальное число проходов 1–3, на практике
больше. Информация передаётся таблицами или скомпилированными командами.

**Ключевые факты.**
- [ ] порядок фаз;
- [ ] грамматический разбор включает синтаксис, семантику и генерацию внутренней формы;
- [ ] деление на анализ и синтез;
- [ ] виды объектных модулей;
- [ ] число проходов и формы передачи информации.

**Ошибки.**
- оптимизация поставлена до разбора;
- грамматический разбор сведён только к синтаксическому анализу;
- объектный модуль только один (например, только машинный код).

## 13. Синтаксис и семантика. Грамматики. БНФ. Рекурсия

**Вопрос.** Что такое синтаксис и семантика? Дайте определение грамматики,
запишите правила в БНФ, объясните рекурсию и эквивалентные грамматики.

**Эталон.** Синтаксис — правила построения допустимых конструкций, семантика —
их смысл. Формальный язык — множество цепочек над конечным алфавитом.
Грамматика — конечное множество правил, порождающих все допустимые
предложения; формально G = (VT, VN, S, P), где S — начальный символ. В БНФ
правило имеет вид «левая часть ::= правая часть», используются угловые скобки,
альтернатива `|` и ε. Рекурсия позволяет конечным набором правил описать
бесконечный язык; она бывает левой, правой и с самовосстановлением.
Эквивалентные грамматики описывают один и тот же язык.

**Ключевые факты.**
- [ ] различие синтаксиса и семантики;
- [ ] G = (VT, VN, S, P) и смысл компонентов;
- [ ] запись БНФ: `::=`, угловые скобки, `|`, ε;
- [ ] зачем нужна рекурсия и её типы;
- [ ] определение эквивалентных грамматик.

**Ошибки.**
- грамматика описана как средство задания семантики;
- ε названо «пустым множеством символов алфавита» вместо пустой цепочки;
- эквивалентность понята как совпадение правил, а не языка.

## 14. Классификация грамматик и языков по Хомскому

**Вопрос.** Приведите классификацию грамматик по Хомскому, соответствующую
классификацию языков и примеры.

**Эталон.** Тип 0 — без ограничений, машина Тьюринга; тип 1 —
контекстно-зависимые (неукорачивающие), машина Тьюринга с конечной лентой;
тип 2 — контекстно-независимые, автомат со стековой памятью; тип 3 —
автоматные (регулярные), конечный автомат. Типы идут по убыванию мощности;
для языков программирования используют типы 3 и 2. Примеры: десятичные числа
и идентификаторы — тип 3, скобочные арифметические выражения — тип 2,
L3 = {a^(2^n)} и L4 = {a^n b^n c^n} — тип 1. Тип языка определяется по
эквивалентной грамматике наименьшей мощности.

**Ключевые факты.**
- [ ] четыре типа и ограничения на правила;
- [ ] соответствие «тип → распознающий агрегат» (0 — МТ, 1 — МТ с конечной лентой, 2 — автомат со стеком, 3 — конечный автомат);
- [ ] порядок по убыванию мощности и использование типов 2–3;
- [ ] хотя бы по одному примеру грамматики и языка;
- [ ] тип языка — по грамматике наименьшей мощности.

**Ошибки.**
- тип 2 распознаётся конечным автоматом, тип 3 — автоматом со стеком;
- тип языка определяется по любой его грамматике;
- утверждается, что для языков программирования нужен тип 1.

## 15. Лексический анализ. Диаграмма состояний

**Вопрос.** Что такое лексический анализ? Как диаграмма состояний задаёт
работу анализатора?

**Эталон.** Лексический анализ разделяет элементы входной программы на
синтаксические классы и формирует однородное представление. Лексема — неделимая
словарная единица, синтаксический класс — группа однотипных лексем. Лексика
описывается автоматными грамматиками, поэтому распознаватель — конечный
автомат. Диаграмма состояний — ориентированный граф: вершины — состояния,
дуги помечены входными символами, отмечены начальное и заключительные
состояния; цепочка принята, если после её конца автомат в заключительном
состоянии. На дугах задаются действия: накопить литеру, занести имя в таблицу,
выдать лексему.

**Ключевые факты.**
- [ ] определение лексического анализа и понятия лексемы/класса;
- [ ] лексика — автоматная грамматика, распознаватель — конечный автомат;
- [ ] диаграмма состояний: состояния, дуги, начальное и заключительные состояния;
- [ ] правило перехода и принятия цепочки;
- [ ] действия на дугах.

**Ошибки.**
- лексический анализ строит синтаксическое дерево;
- диаграмма состояний задаёт грамматику типа 2;
- цепочка принимается при попадании в любое состояние.

**Не ошибка.** Пример сканера с состояниями 0/1/2 и код 0 как конец потока.

## 16. Лексический анализ. Матрица переходов

**Вопрос.** Что такое матрица переходов лексического анализатора и как по ней
работает анализатор?

**Эталон.** Матрица переходов — табличный способ задания того же конечного
автомата. Строки — состояния, столбцы — входные символы или их классы, в клетке
следующее состояние и при необходимости действие; пустая клетка означает
ошибку. Для компилятора это постоянная таблица. Анализатор начинает с
начального состояния и для каждой литеры выполняет присваивание «состояние :=
матрица[состояние, класс]». Достоинство: программа автомата универсальна, при
изменении лексики меняется только таблица; диаграмма удобна человеку, матрица
— машине.

**Ключевые факты.**
- [ ] строки — состояния, столбцы — символы/классы;
- [ ] в клетке следующее состояние и действие;
- [ ] отсутствие перехода — ошибка;
- [ ] матрица — постоянная таблица лексического анализа;
- [ ] универсальность программы при смене таблицы.

**Ошибки.**
- строки матрицы — лексемы, столбцы — состояния;
- матрица хранит таблицу имён;
- матрица задаёт грамматику типа 2.

**Не ошибка.** Конкретный пример автомата A–D или матрица сканера 0/1/2.

## 17. Грамматический разбор: понятия и методы

**Вопрос.** Что такое грамматический разбор? Объясните синтаксическое дерево,
канонический разбор и методы «сверху-вниз» и «снизу-вверх».

**Эталон.** Грамматический разбор восстанавливает синтаксическое дерево
предложения в заданной грамматике. Корень дерева — начальный символ,
внутренние вершины — нетерминалы, листья — терминалы. Разбор «сверху-вниз»
идёт от корня к листьям (цели и подцели, левый вывод; примеры — возвраты,
рекурсивный спуск), «снизу-вверх» — от листьев к корню (поиск основы и
свёртка; пример — грамматики предшествования). Канонический разбор снизу-вверх
сворачивает самую левую основу и является обращением правого вывода; для
разбора сверху-вниз канонический порядок — всегда раскрывать самый левый
нетерминал.

**Ключевые факты.**
- [ ] определение разбора через восстановление дерева;
- [ ] корень — аксиома, внутренние вершины — нетерминалы, листья — терминалы;
- [ ] направления «сверху-вниз» и «снизу-вверх» и что откуда строится;
- [ ] канонический разбор: самая левая основа / обращение правого вывода;
- [ ] хотя бы один пример метода для каждого направления.

**Ошибки.**
- «сверху-вниз» начинается с листьев;
- канонический разбор — любой порядок;
- корень дерева — первый терминал предложения.

**Не ошибка.** Формы представления дерева (граф, скобочная запись, матрица,
списки) и упоминание неоднозначности.

## 18. Разбор сверху-вниз с возвратами

**Вопрос.** Опишите грамматический разбор сверху-вниз с возвратами и приведите
пример.

**Эталон.** Разбор управляется правилами грамматики: на каждом шаге ставится
цель, нетерминал раскрывается в подцели по правилам, пока не останутся
терминалы. Если цель недостижима, происходит возврат и проверяется следующая
альтернатива; если исчерпаны все — предложение некорректно. Пример: число
−123.45 разбирается по грамматике десятичных чисел с возвратами при выборе
знака и при переходе от рекурсивного правила к конечному; выражение i + i * i
требует 40 шагов. Особенности: важен порядок альтернатив, прямая левая
рекурсия невозможна, скорость мала; ускорение — заглядывание вперёд,
преобразование грамматики, рекурсивный спуск.

**Ключевые факты.**
- [ ] цели и подцели по правилам грамматики;
- [ ] возврат при недостижимой цели и перебор альтернатив;
- [ ] пример с конкретным шагом возврата;
- [ ] невозможность прямой левой рекурсии;
- [ ] низкая скорость и способы ускорения.

**Ошибки.**
- метод не делает возвратов;
- прямая левая рекурсия названа допустимой;
- пример описан без единого возврата.

**Не ошибка.** Любой корректный пример (−123.45 или i + i * i) и любая
эквивалентная формулировка шагов.

## 19. Грамматики предшествования

**Вопрос.** Что такое грамматики предшествования и как по ним выполняется
разбор «снизу-вверх»?

**Эталон.** Между соседними символами возможны отношения `>`, `<`, `==` или
отсутствие отношения; если для любой пары символов отношение определено
однозначно, можно построить анализатор снизу-вверх. В грамматиках операторного
предшествования отношения зависят только от операторов. Разбор: текст
просматривается слева направо до конца основы, затем назад до начала основы,
символы между ними сворачиваются, просмотр продолжается. Для `# i + i * i \n`
получаются свёртки T1 = i * i и T2 = i + T1; результат — дерево с корнем «+».
Алгоритм реализуется автоматом со стековой памятью.

**Ключевые факты.**
- [ ] четыре варианта отношений между соседними символами;
- [ ] операторное предшествование зависит только от операторов;
- [ ] алгоритм: вперёд до конца основы, назад до начала, свёртка;
- [ ] пример свёрток (T1 = i * i, T2 = i + T1);
- [ ] разбор снизу-вверх, автомат со стеком.

**Ошибки.**
- отношения зависят от операндов;
- свёртка делается без обратного просмотра;
- пример даёт T1 = i + i (известная описка рукописного листа).

## 20. Машинно-независимая оптимизация

**Вопрос.** Что такое машинно-независимая оптимизация и как она выполняется?
Приведите пример.

**Эталон.** Это преобразование внутренней формы в более экономную без
изменения смысла программы и без учёта системы команд. Шаги: найти границы
предложений, упорядочить операнды коммутативных операций, исключить
повторяющиеся тройки и скорректировать указатели, вычислить операции над
литералами, повторять до отсутствия изменений. Пример: для `A = (A + C) + 20 *
30; B = (A + C) – (C + A) * D` исключается повтор `C + A`, а `20 * 30`
заменяется литералом 600; число команд сокращается с 9 до 7, ячеек временной
памяти — с 9 до 5.

**Ключевые факты.**
- [ ] оптимизация не меняет смысл программы;
- [ ] не зависит от системы команд;
- [ ] исключение общих подвыражений;
- [ ] вычисление констант во время компиляции;
- [ ] числа примера: 9 → 7 команд и 9 → 5 ячеек (или сам результат: 600 и исключение повтора).

**Ошибки.**
- оптимизация учитывает число регистров;
- меняется смысл программы;
- строки T1 и T5 объединяются, хотя между ними A переопределяется.

## 21. Генерация кода и машинно-зависимая оптимизация

**Вопрос.** Как выполняется генерация кода и машинно-зависимая оптимизация при
одном и при нескольких РОНах?

**Эталон.** Генерация кода переводит внутреннюю форму в команды целевой ЭВМ по
таблицам порождаемого кода; шаблон зависит от адресности (3, 2, 1 адреса).
Неоптимизированная генерация эквивалентна безусловным вызовам макросов,
оптимизирующая — условным: вариант выбирается по условиям (операнд уже в
регистре, нужно ли сохранять результат, есть ли свободный РОН, совпадают ли
типы и длины, быстродействие команд). При одном РОНе для `X + Y * (Z + X) + A`
код сокращается с 12 команд и 4 ячеек до 6 команд и 1 ячейки: промежуточный
результат остаётся в регистре. При нескольких РОНах генератор ведёт учёт
содержимого регистров, оставляет результаты в свободных регистрах и освобождает
регистр записью в память, когда свободных нет.

**Ключевые факты.**
- [ ] генерация по таблицам порождаемого кода, зависимость от адресности;
- [ ] неоптимизированный код = безусловные макросы, оптимизированный = условные;
- [ ] типовые условия выбора варианта;
- [ ] пример с одним РОНом: 12 → 6 команд, 4 → 1 ячейка;
- [ ] при нескольких РОНах — учёт занятости регистров и запись в память при нехватке.

**Ошибки.**
- машинно-зависимая оптимизация названа независимой от ЭВМ;
- в примере с одним РОНом остаются 4 ячейки;
- при нескольких РОНах регистры не учитываются.

**Не ошибка.** Ответ без числовых значений, если идея «результат остаётся в
регистре» передана верно.

## 22. Распределение памяти как фаза компилятора

**Вопрос.** Как распределяется память в компиляторе и какие бывают классы
памяти?

**Эталон.** Глубина распределения зависит от выходного модуля: для машинного
кода нужна полная фактическая раскладка, для текста на ассемблере — только
символическая. Память нужна командам, литералам, ячейкам временной памяти,
переменным и массивам. Классы: статическая (внутренняя и внешняя,
резервируется на всё время выполнения), динамическая (внутренняя, на время
работы процедуры, стек и области инициализации, допускает рекурсию) и
управляемая (ALLOCATE/FREE). Фаза получает оптимизированную внутреннюю форму и
работает с таблицами имён и литералов.

**Ключевые факты.**
- [ ] зависимость от вида объектного модуля;
- [ ] четыре группы элементов, которым нужна память;
- [ ] статическая: внутренняя/внешняя, на всё время выполнения;
- [ ] динамическая: внутренняя, на время процедуры, стек, рекурсия;
- [ ] управляемая: ALLOCATE/FREE.

**Ошибки.**
- статическая память выделяется при выполнении;
- динамическая названа внешней;
- управляемая память отождествлена с динамической.

## 23. Потоки информации при компиляции

**Вопрос.** Опишите потоки информации при компиляции: постоянные и динамические
таблицы, фазы, основной поток.

**Эталон.** Схема состоит из трёх слоёв: постоянные таблицы, фазы, динамические
таблицы. Фазы: лексический анализ → синтаксический анализ → интерпретация →
машинно-независимая оптимизация → распределение памяти → генерация кода и
машинно-зависимая оптимизация → трансляция с языка ассемблера. Постоянные
таблицы: терминальные символы и матрица переходов, грамматики и правила
предшествования, правила оптимизации, таблицы порождаемого кода, таблицы
ассемблера. Динамические: входная программа, таблица однородных символов,
таблица имён, таблица литералов, стек, внутренняя и оптимизированная форма,
программа на ассемблере, объектный модуль. Основной поток: входная программа →
однородные символы → внутренняя форма → оптимизированная форма → ассемблер →
объектный модуль.

**Ключевые факты.**
- [ ] три слоя схемы;
- [ ] порядок фаз, включая «трансляцию с языка ассемблера»;
- [ ] хотя бы три постоянные таблицы и их привязка к фазам;
- [ ] цепочка динамических объектов от входной программы до объектного модуля;
- [ ] формы передачи информации: таблицы или скомпилированные команды.

**Ошибки.**
- схема заканчивается генерацией кода, без трансляции с ассемблера;
- динамические таблицы названы постоянными;
- перепутаны места таблицы имён и таблицы однородных символов.

**Не ошибка.** Трактовка фазы «интерпретация» как семантического анализа и
генерации внутренней формы (в схеме она не расшифрована).

## 24. Интерпретаторы. Польская запись. Вычисление в ОПЗ

**Вопрос.** Что такое интерпретатор? Что такое польская запись и как вычислить
выражение в обратной польской записи?

**Эталон.** Интерпретатор совмещает трансляцию и выполнение: операторы
транслируются и сразу выполняются, результаты трансляции не сохраняются,
поэтому циклы работают медленнее. Применяется в обучении, отладке и
интерфейсах. Запись бывает префиксной и постфиксной (ОПЗ); ОПЗ бесскобочная,
порядок операндов сохраняется. Вычисление: просмотр слева направо, операнд
кладётся в стек, оператор снимает операнды с вершины и кладёт результат; в
конце в стеке значение. Пример: `A * (–B + C / D)` → `A B @ C D / + *`.

**Ключевые факты.**
- [ ] интерпретатор совмещает трансляцию и выполнение;
- [ ] результаты трансляции не сохраняются, циклы медленнее;
- [ ] ОПЗ бесскобочная, порядок операндов сохраняется;
- [ ] алгоритм со стеком;
- [ ] пример перевода и вычисления, включая `@` для унарного минуса.

**Ошибки.**
- интерпретатор сначала строит объектный модуль;
- ОПЗ требует скобок;
- операнды в ОПЗ идут в обратном порядке.

## 25. Преобразование инфиксной записи в польскую

**Вопрос.** Как перевести инфиксную запись в обратную польскую?

**Эталон.** Используется алгоритм сортировочной станции (Дейкстра): нужны
выходная строка и стек операторов. Операнд сразу идёт в выход; оператор
выталкивает из стека операторы с приоритетом выше или равным (при равенстве —
для левоассоциативного), затем кладётся в стек; открывающая скобка кладётся в
стек; закрывающая выталкивает операторы до открывающей, которая удаляется; в
конце стек выталкивается в выход. Умножение и деление старше сложения и
вычитания. Пример: `(A + B) * (C + D)` → `AB+CD+*`.

**Ключевые факты.**
- [ ] алгоритм сортировочной станции и стек операторов;
- [ ] правило выталкивания по приоритету;
- [ ] обработка скобок;
- [ ] выталкивание остатка стека в конце;
- [ ] корректный пример перевода.

**Ошибки.**
- для перевода нужны два просмотра;
- скобки попадают в выходную строку;
- при равенстве приоритетов выталкивание не делается для левоассоциативных операторов.

**Не ошибка.** Ссылка на транслирующую грамматику как второй способ.

## 26. Синтаксические диаграммы

**Вопрос.** Что такое синтаксические диаграммы и что они отображают?

**Эталон.** Для каждого нетерминала диаграмма задаёт помеченный граф с одним
входом и одним выходом; последовательность пометок на пути от входа к выходу —
возможная подстрока, которой заменяется нетерминал. Диаграммы отображают
порождающие правила грамматики и процесс распознавания (трансляции).
Терминалы изображаются кругами или овалами, нетерминалы — квадратами или
прямоугольниками. Типовые конструкции: последовательность, выбор, необязательный
элемент `[ ]`, повторение `{ }`. Пример — диаграмма десятичных чисел с точками
«Инициация», P1–P3.

**Ключевые факты.**
- [ ] граф с одним входом и выходом для каждого нетерминала;
- [ ] путь задаёт допустимую подстроку;
- [ ] два назначения: правила грамматики и процесс трансляции;
- [ ] терминалы — круги/овалы, нетерминалы — прямоугольники;
- [ ] соответствие конструкций и БНФ (выбор, `[ ]`, `{ }`).

**Ошибки.**
- терминалы изображены прямоугольниками;
- диаграмма описывает семантику, а не синтаксис;
- диаграмма не связана с процессом распознавания.

**Не ошибка.** Трактовка точек P1–P3 как мест выполнения действий (в материале
не расшифровано).

## 27. Рекурсивный спуск

**Вопрос.** Что такое рекурсивный спуск и как по синтаксическим диаграммам
строят программу разбора?

**Эталон.** Рекурсивный спуск — безвозвратный разбор сверху-вниз; он устраняет
медлительность возвратов ценой ограничений на грамматику. Каждому нетерминалу
соответствует процедура: терминал — проверить и прочитать лексему, нетерминал —
вызвать процедуру, последовательность — последовательные операторы,
разветвление — условный оператор, цикл — оператор цикла. Альтернатива
выбирается по текущей лексеме без возвратов. Ограничения: множества первых
символов альтернатив не пересекаются, левая рекурсия недопустима (заменяется
правой рекурсией или циклом). Действия трансляции вставляются в те же
процедуры.

**Ключевые факты.**
- [ ] безвозвратный разбор сверху-вниз;
- [ ] процедура на каждый нетерминал;
- [ ] отображение конструкций диаграммы в операторы;
- [ ] выбор альтернативы по текущей лексеме;
- [ ] запрет левой рекурсии и требование различимых первых символов;
- [ ] действия трансляции внутри процедур.

**Ошибки.**
- рекурсивный спуск использует возвраты;
- левая рекурсия допустима;
- процедуры строятся по таблице предшествования.

**Не ошибка.** Пример с грамматикой `<M> ::= <ОД> { + <ОД> }` и процедурами
М/ОД/С.

## 28. Внутренние формы: матрица, ОПЗ, списковые структуры

**Вопрос.** Какие внутренние формы программы используются в компиляторах:
матрица синтаксического дерева, ОПЗ, списковые структуры?

**Эталон.** Матрица синтаксического дерева — таблица, где строка описывает
операцию: ячейка временной памяти, оператор, два операнда (тетрада); без
ячейки — триада. Указатели вперёд и назад необязательны и нужны для
оптимизации. ОПЗ — бесскобочная постфиксная запись, получается и вычисляется за
один просмотр, применяется в интерпретаторах. Списковая структура — связанный
список из информационной части и указателей; для `(X + Y * Z) * (A + B)`
получаются подсписки L1–L4, а код генерируется от подсписка с наибольшим
номером, то есть команды идут в порядке убывания номеров.

**Ключевые факты.**
- [ ] матрица: строка = операция, тетрада из 4 элементов, триада из 3;
- [ ] указатели вперёд/назад нужны для оптимизации;
- [ ] ОПЗ: бесскобочная, один просмотр, стек, интерпретаторы;
- [ ] списки: информационная часть + указатели, односвязный/многосвязный;
- [ ] пример списков L1–L4 и порядок генерации по убыванию номеров.

**Ошибки.**
- тетрада названа тройкой «оператор + два операнда»;
- ОПЗ требует скобок или обратного порядка операндов;
- код по спискам генерируется от меньшего номера к большему.

## 29. Транслирующие грамматики. Синтаксически управляемый перевод

**Вопрос.** Что такое синтаксически управляемый перевод и транслирующая
грамматика? Приведите пример.

**Эталон.** Синтаксически управляемый перевод — организация трансляции, при
которой действия привязаны к правилам грамматики и выполняются при разборе.
Транслирующая грамматика — контекстно-свободная грамматика, терминалы которой
делятся на входные символы и символы действия `{…}`; цепочка из входных
символов и действий — последовательность актов, а без символов действия
получается входная грамматика. Пример — перевод инфиксных многочленов в ОПЗ:
для `A + B * D` последовательность актов `A {A} + B {B} * D {D} {*} {+}` даёт
`A B D * +`. Для новой входной грамматики транслирующую строят заново.
Практический пример — yacc с действиями на C.

**Ключевые факты.**
- [ ] действия привязаны к правилам и выполняются при разборе;
- [ ] транслирующая грамматика — КС-грамматика с двумя типами терминалов;
- [ ] символы действия в фигурных скобках;
- [ ] входная грамматика получается удалением действий;
- [ ] пример перевода в ОПЗ с последовательностью актов.

**Ошибки.**
- символы действия названы нетерминалами;
- транслирующая грамматика названа контекстно-зависимой;
- действия выполняются после разбора, а не по ходу.

**Не ошибка.** Упоминание yacc, «компиляторов компиляторов» и АТГ как
следующего шага.

## 30. Атрибутные транслирующие грамматики

**Вопрос.** Что такое атрибутная транслирующая грамматика и как её строят?

**Эталон.** В обычной грамматике есть только синтаксические классы, а для
трансляции нужны значения — атрибуты символов. АТГ — транслирующая грамматика
с атрибутами и правилами их вычисления. Атрибуты бывают синтезируемые
(вычисляются от листьев к корню) и наследуемые (от корня к листьям). Строят в
три этапа: входная грамматика → транслирующая грамматика → АТГ (перечислить
нетерминалы с атрибутами и типами, задать правила; используется стрелка ←).
Пример — перевод выражений в цепочку атомов: у нетерминалов синтезируемый
указатель на элемент таблицы, у действий `{СЛОЖИТЬ}` и `{УМНОЖИТЬ}` —
наследуемые указатели на левый операнд, правый операнд и результат; для
`(a + b) * (a + c)` получается `СЛОЖИТЬ(1,2,3) СЛОЖИТЬ(1,4,5)
УМНОЖИТЬ(3,5,6)`.

**Ключевые факты.**
- [ ] атрибут — значение символа, нужное для трансляции;
- [ ] АТГ = транслирующая грамматика + атрибуты + правила вычисления;
- [ ] два типа атрибутов и направления вычисления;
- [ ] три этапа конструирования;
- [ ] пример с атомами и указателями (или эквивалентный пример);
- [ ] теоретическое значение для автоматизации построения трансляторов.

**Ошибки.**
- атрибуты только синтезируемые;
- АТГ названа грамматикой без символов действия;
- правила вычисления задаются знаком `=` без пояснения (допустимо, но
  предпочтительна стрелка ←).

**Не ошибка.** Аналогия с `$1`, `$$` в yacc.

## 31. Синтезируемые атрибуты

**Вопрос.** Что такое синтезируемые атрибуты? Приведите пример.

**Эталон.** Синтезируемые атрибуты вычисляются при движении по дереву от
листьев к корню: атрибут нетерминала в левой части правила вычисляется через
атрибуты символов правой части, правила связаны с левой частью продукции.
Исходные значения приходят от лексического блока как атрибуты лексем. Пример —
вычисление значения выражения: у `<M>`, `<ОД>`, `<С>` по одному синтезируемому
атрибуту, правила `r ← p + q`, `r ← p * q`, `r ← p`; для `(10 + 12) * (7 + 8)`
значение поднимается вверх и `{ОТВЕТ}` получает 330.

**Ключевые факты.**
- [ ] направление от листьев к корню;
- [ ] атрибут левой части вычисляется через правую;
- [ ] правила связаны с нетерминалом левой части;
- [ ] начальные значения — атрибуты лексем от лексического блока;
- [ ] пример и результат 330 (или корректный аналог).

**Ошибки.**
- синтезируемые атрибуты идут от корня к листьям;
- вычисляются через родителя, а не через потомков;
- правила привязаны к правой части.

## 32. Наследуемые атрибуты

**Вопрос.** Что такое наследуемые атрибуты? Приведите пример.

**Эталон.** Наследуемые атрибуты вычисляются при движении по дереву от корня к
листьям: значение атрибута символа правой части определяется символами выше в
дереве или символами той же правой части; правила связаны с нетерминалами
правой части. Пример — описания переменных `ТИП V, V, V`: тип нужно передать
вниз, поэтому `<список переменных>` получает наследуемый атрибут типа, и для
каждой переменной порождается `{УСТАНОВИТЬ-ТИП}`. Для
`ТИП(вещественный) V1, V2, V3` получаются действия
`УСТАНОВИТЬ-ТИП(1, вещественный)`, `(2, вещественный)`, `(3, вещественный)`.
В одной грамматике могут быть оба вида атрибутов.

**Ключевые факты.**
- [ ] направление от корня к листьям;
- [ ] значение берётся у символов выше или той же правой части;
- [ ] правила связаны с нетерминалами правой части;
- [ ] пример с передачей типа вниз по списку переменных;
- [ ] действия УСТАНОВИТЬ-ТИП для всех переменных с одним типом.

**Ошибки.**
- наследуемые атрибуты идут от листьев к корню;
- тип «вычисляется» из имён переменных, а не передаётся сверху;
- в примере тип устанавливается только первой переменной.
